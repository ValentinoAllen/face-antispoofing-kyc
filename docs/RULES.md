# Engineering Rules

These rules apply to every change in this repository. If a rule blocks legitimate work, change the
rule in a commit that explains why. Do not quietly ignore it.

## 1. Coding conventions

**Naming**
- Modules, functions and variables use `snake_case`. Classes use `PascalCase`. Constants use
  `UPPER_SNAKE_CASE`.
- Names say what something is, not its type: `subject_ids`, not `id_list`. Abbreviations are allowed
  only when they are domain terms (`apcer`, `bpcer`, `bbox`, `onnx`).
- Private helpers are prefixed with `_`.

**Typing**
- Every function signature in `src/` is fully type-annotated, including return types.
- `mypy` must pass on `src/antispoof` with the settings in `pyproject.toml`.
- Use `pathlib.Path` for filesystem paths, not `str`.
- Use `dataclasses` (or pydantic models in `serving/`) instead of loose dicts for structured data
  that crosses function boundaries.

**Docstrings**
- Every public module, class and function in `src/` has a Google-style docstring. Include
  `Args:`, `Returns:` and `Raises:` where they apply.
- Metric functions state their definition and cite the standard, e.g. "APCER per ISO/IEC 30107-3".

**Size and structure**
- Functions have a hard maximum of **50 lines** including the docstring. Split anything longer.
- One responsibility per function. I/O, computation and plotting live in separate functions.
- No `print` in `src/`; use `logging`.
- No logic in `scripts/` beyond argument parsing and calling `src/antispoof`. No logic in notebooks
  that other code depends on.

**Formatting and lint**
- `ruff format` and `ruff check` pass, with line length 100.
- No blanket `# noqa` or `# type: ignore`; each one names a specific code and gives a reason.

## 2. The config rule

- **Every hyperparameter lives in a YAML file under `configs/`.** This includes data paths, input
  size, crop margin, augmentation parameters, model/backbone name, optimizer, learning rate and
  schedule, batch size, epochs, loss weights, seed, threshold rule, and quantization settings.
- **Training, evaluation and export code contain zero hardcoded hyperparameter values.** A number
  that changes model behaviour and appears as a literal in `src/` is a bug.
- Configs are immutable once a run has cited them. To change settings, copy the file under a new
  name.
- CLI overrides are allowed for local debugging only. A run that used overrides records the fully
  resolved config, and that resolved config is what gets hashed.
- Machine-specific paths (Kaggle vs local) are handled by a small per-environment config that the
  experiment config includes, not by `if` branches in code.

## 3. Reproducibility rules

- **Seed everything** through one function: Python `random`, NumPy, PyTorch CPU/CUDA/MPS, and
  DataLoader worker seeding. The seed comes from the config.
- Enable deterministic algorithms where the platform supports it. Record in the run record where
  they could not be enabled.
- **Every run records** `git_sha`, `git_dirty`, `config_hash`, `split_sha256`, `seed` and library
  versions (see `SCHEMA.md` §3).
- Runs launched with a dirty working tree are marked `git_dirty: true` and cannot be cited as results
  in docs or the README.
- **The test split is evaluated once**, for the final model. Model selection, threshold choice and
  early stopping use validation only.
- Manifests and splits are regenerated by scripts. They are never edited by hand.
- Artifacts (`*.pt`, `*.onnx`) are never committed. They are referenced by path or W&B artifact in the
  run record.

## 4. Testing rules

- **Every data-splitting function and every metric function must have a test** before it is used in a
  run.
  - Splits: disjointness, full coverage of subjects, determinism for a fixed seed, and edge cases
    (single-image subjects, tiny datasets).
  - Metrics: hand-computed expected values on small synthetic inputs, edge cases (no attacks of a
    species, all-correct, all-wrong), and the threshold boundary convention (`>=`).
- Tests never read from `data/`. They use synthetic fixtures built in the test or in
  `tests/conftest.py`.
- Tests that take more than a few seconds are marked `@pytest.mark.slow`.
- API contract tests validate responses against the schemas in `SCHEMA.md` §4.
- A bug fix comes with a test that fails without the fix.
- `uv run pytest` passes before every commit to `main`.

## 5. Git rules

- Small commits with imperative subject lines ("Add subject-disjoint split builder").
- Never commit `data/`, model weights, W&B directories or credentials. `.gitignore` covers these;
  check `git status` anyway.
- After cloning, run `git config core.hooksPath .githooks` so the commit-msg hook is active.

## 6. Constraints for AI assistants

Any AI coding assistant working in this repository must follow these constraints. They override the
assistant's defaults.

1. **Commit attribution.**
   - Never add `Co-Authored-By: Claude` (or any AI co-author) to a commit message.
   - Never add a "Generated with …" footer, a `Claude-Session:` trailer, or any URL pointing to an
     assistant session.
   - Never mention Claude, Claude Code, Anthropic or AI assistance in commit messages, PR
     descriptions or the README.
   - Write commit messages as the repository owner, in plain imperative style.
   - Do not bypass the commit-msg hook (`--no-verify` is forbidden).
2. **No invented numbers.**
   - Never write a metric, latency, model size, dataset statistic, count or result into any doc,
     report, README or ledger unless it was produced by code run in this repository and can be
     traced to a run record or script output.
   - When a value is unknown, write `TBD — decide before <milestone>`.
   - Metric tables stay empty until real results exist.
3. **Do not touch `data/`.** Do not read, write, move or delete anything under `data/` unless the
   repository owner explicitly asks for that specific operation in the current session.
4. **Update `docs/PROGRESS.md` before ending any working session.**
   - Rewrite `## Current status`.
   - Prepend a session-log entry that records only what actually happened.
   - Add completed runs to `docs/EXPERIMENTS.md`.
   - Use `/session-end` for this.
5. **Do not push or add remotes.** The repository owner does that.
6. **Ask when a decision belongs to the owner** (targets, scope, dataset handling, public-facing
   wording) instead of guessing.
7. **Figures measured outside this repository.**
   - Any figure measured outside this repository (for example by the owner on Kaggle, before the
     in-repo tooling existed) carries a provenance line. The line states who measured it, on what
     date, against which artifact, and the command that will reproduce it in-repo.
   - Mark such figures **"externally measured, not yet reproduced in-repo"**. Remove the mark only
     once code in this repository has printed matching values, as item 2 requires, and cite that
     output.
   - If the in-repo output disagrees, record both values and the discrepancy. Never silently
     overwrite either.
